智能体循环详解：从 ReAct 到循环工程（2026 指南）
核心要点
智能体循环 = 触发器 + 可验证目标。智能体持续运行直到目标达成——无需人工提示。

循环工程是指设计这些循环的实践：指定目标、设置触发器、构建防止其无限运行的防护栏。

从 ReAct（2022）到 Ralph Loop 和 OpenAI 的 /goal 命令，共有 10 种不同类型的智能体循环。

没有防护栏的循环必然会失败。无限循环、目标漂移和令牌成本爆炸是生产环境中常见的问题——而不是边缘情况。

今年早些时候，AI 编码领域核心人物的两篇帖子引发了一场持续至今的讨论。

Anthropic 旗下 Claude Code 的创造者 Boris Cherny 说：“我不再直接提示 Claude 了。我有循环在运行。是它们负责提示 Claude 并自己决定下一步做什么。我的工作是写循环。”

OpenClaw 的创始人 Peter Steinberger 对他的数百万粉丝说：

这是你的月度提醒：你不应该再亲自提示编码智能体了。
你应该设计循环来提示你的智能体。

—— Peter Steinberger 🦞 (@steipete) 2026 年 6 月 7 日

Steinberger 的帖子在不到 24 小时内获得了 500 万次浏览量。突然间，各地的开发者都在问：什么是循环？为什么它很重要？

本指南回答了这两个问题，并逐一拆解了每一种主要类型的智能体循环，以及循环工程在实践中实际包含的内容。

什么是智能体循环？
智能体循环比听起来要简单。它只需要两样东西：

触发器：启动循环的东西（PR 开启、定时计划、人类说“开始”）

可验证目标：一个已定义的终态，智能体朝之努力

智能体不会等待你的下一条消息。它启动、运行、检查目标是否已达到，如果没有，就再次循环，直到达成目标或直到某个停止条件触发。

你给智能体的是一个目标，而不是一条提示词。它自己弄清楚步骤、执行它们、检查自己的工作，然后继续前进。

这就是它与提示工程的区别。在旧工作流中，你会提示你的智能体，等待它完成，然后再提示。循环工程的目标是减少你的参与。

确定性目标很容易：所有测试通过、CI 变绿、函数运行无错误。困难的部分是当目标像“构建这个功能”时——定义“完成”实际长什么样需要事先编写完整的规格说明。这正是循环工程困难且有价值的原因。

要理解是什么让循环在模型层面成为可能，首先需要理解智能体 LLM 实际上是什么，以及它们与标准语言模型有何不同。

循环 vs 自动化：有什么区别？
值得澄清，因为两者很容易混淆。

自动化执行一系列步骤。它运行一个脚本。它遵循一个配方。它不做任何决策。

循环内部包含决策。智能体主动判断它是否已达到目标。它不只是执行——它在评估、循环、并根据发现进行调整。

三种触发器类型
每个智能体循环都从一个触发器开始。只有三种：

事件驱动——发生了某事：PR 开启、文件变更、API 调用完成

定时驱动——cron 任务触发：每 30 分钟、每小时、每天

人工启动——你输入一个目标然后说“开始”

Claude Code 的 /loop 命令是人工启动类型的最简形式：/loop every 5 minutes, compare what we have built with our full spec and continue building until we complete it.

智能体循环内部如何工作
智能体循环的 5 个阶段
每个智能体循环都经历五个阶段，重复直到满足停止条件。

感知——接收输入：用户目标、工具结果、API 响应、或上一步的错误。

推理——思考输入意味着什么、它已经知道什么、还需要什么、有哪些选项。

规划——选择下一步做什么。简单循环只选一个步骤。复杂架构产生完整的任务分解。

行动——执行：调用工具、写文件、运行代码、查询数据库、或协调其他智能体。

观察——接收结果并更新其理解。成功则向前推进。失败则触发关于失败原因的推理。

然后循环回到第 1 步。

这种结构与强化学习有直接的相似性。一个循环需要一个可验证的奖励信号——相当于知道目标何时达成。奖励可以是确定性的（测试通过、无类型错误）或非确定性的（LLM 评估输出是否满足目标）。

循环何时停止？
LLM 没有内置的“完成”概念。没有明确的停止条件，循环会一直运行到钱花光为止。

每个生产级智能体循环都需要：

硬性的迭代次数上限

每次运行的令牌和成本预算

无进展检测（如果迭代间没有任何变化则退出）

对照可验证标准进行目标达成检查

任务级别和单个工具调用级别的超时

“让智能体自己决定什么时候完成”是一个能让你在想清楚之前就耗尽令牌上限的策略。下面介绍的每一种循环类型，部分就是为了解决这个问题而构建的。

每种智能体循环详解
第一代：概念验证（2023）
AutoGPT
发布于 2023 年 3 月 30 日。第一个将循环概念呈现在数百万开发者面前的循环。

工作原理：

给 GPT-4 一个高层次目标

它将目标分解为子任务

使用工具执行：网页浏览、文件管理

反思结果并循环

AutoGPT 在几个月内获得了 10 万 GitHub Star。它证明了需求是真实的。

然而，AutoGPT 并未被日常用户广泛采用，因为它昂贵且不可靠。用户抱怨它经常陷入无限循环并产生巨额 API 账单。

虽然这个开源概念为现代循环铺平了道路，但它更像一个引人入胜的技术实验，而不是一个可靠的生产力工具。

第二代：学术框架（2022-2023）
ReAct
发表于 2022 年 10 月 6 日——比 AutoGPT 早五个月。来自普林斯顿大学和 Google Research。

ReAct 代表 推理 + 行动（Reasoning + Acting）。在每一步，智能体产生两样东西：

推理轨迹：“在调用这个端点之前我需要检查 API 速率限制”

具体行动：实际的工具调用或搜索

每个行动的观察结果反馈到下一步的推理中。当返回意外结果时，智能体可以推理原因，而不是盲目重试。

结果：在 ALFWorld 上提升 34%，在 WebShop 上比仅行动方法提升 10%。

ReAct 是 LangChain 的 AgentExecutor 和大多数生产级编码智能体内部的模式。任何循环工程工作的默认起点。

Reflexion
NeurIPS 2023。ReAct 带一个自我评估层。

在任务完成或失败后，智能体生成对出错原因的批判。该批判被存储在记忆中，并注入到下一次尝试的上下文中。

比 ReAct 更昂贵（额外的 LLM 反思调用）

在试错型任务上更好：调试、不熟悉的代码库、创造性问题解决

对于直接的检索任务，通常不值得增加的开销

ReAct 是基础。Reflexion 在上面构建了一个学习层。

Plan-and-Execute
将思考与执行分离。

规划器预先生成完整的任务分解

执行器逐步完成每个步骤

重新规划器在执行偏离计划时进行调整

LangChain 的 LLMCompiler 报告称，通过并行运行独立步骤，比顺序 ReAct 快了 3.6 倍（Kim 等人，ICML 2024）。

权衡：当早期步骤产生意外结果时，适应性较差。Plan-and-Execute 会坚持计划。ReAct 在每一步重新校准。

第三代：架构模式（2024）
OODA 循环
来自美国空军上校 John Boyd：观察、定向、决策、行动（Observe, Orient, Decide, Act）。

其独特的贡献在于定向步骤。大多数循环从观察直接跳到决策。OODA 先插入一个上下文化步骤——智能体在决策之前，根据其目标、约束和先验知识来处理原始观察。

对于复杂、快速变化环境中的智能体，这个额外步骤显著提高了决策质量。

内/外双循环
微软的 Magentic-One 架构。

外循环：战略规划，监控原始目标的进展

内循环：当前策略内的逐步执行

当内循环停滞时，外循环重置整个策略——而不仅仅是重试当前步骤。防止了“坚持失败”模式——即智能体不断重复一个错误的方法，因为它没有机制来退后一步重新思考。

多智能体编排
一个监督者将工作分配给专门的子智能体：规划器、执行器、研究员、验证器。监督者进行协调而非执行。

数据：

Anthropic 的多智能体研究系统在内部评估中比单智能体高出 90.2%

单智能体消耗约 4 倍于标准聊天的令牌

多智能体系统消耗约 15 倍

OpenAI Agents SDK 是目前构建这个编排层最容易上手的框架之一。

多智能体适用于需要并行探索或真正超出单个上下文窗口复杂度的任务。对大多数任务来说是大材小用，成本必须合理。

第四代：实践者循环工程（2025-2026）
Ralph Loop（Ralph Wiggum 技术）
由 Geoffrey Huntley 于 2025 年 7 月发明。以《辛普森一家》中那个一边撞门框一边宣布“我在帮忙！”的角色命名。故意设计得简单，效果却出奇地好。

工作原理：

一个编码智能体在无限的 shell 循环内运行

每次迭代从磁盘读取相同的提示文件

智能体修改代码库然后退出

循环以全新的上下文窗口重新启动

状态存在于文件系统中——代码库、TODO 文件、git 历史

它解决的两个问题：

上下文溢出——长时间会话随着上下文窗口填满而退化。Ralph Loop 每次迭代重置上下文；新会话从磁盘读取当前状态。

过早退出——LLM 在主观上认为任务完成时就会停止。Stop Hook 拦截退出尝试，检查完成标准是否实际满足（测试变绿、覆盖率超过阈值、类型检查干净），如果不满足则重新注入任务提示。

它是在一次黑客松上发布的，但在六个月内迅速成为标准模式。

/goal 命令（OpenAI Codex CLI）和 /loop（Claude Code）
两个直接内置在 AI 编码工具中的持久循环工程原生实现。

Claude Code /goal 于 2026 年 5 月 12 日在 2.1.139 版本中发布。你设置一个完成条件，Claude 在多个轮次中自主工作，直到该条件被满足——过程中跟踪经过时间、轮次和令牌。可在交互模式、-p 标志和远程控制中使用。早期采用者称其为“2026 年被最低估的 AI 功能”，因为它完全消除了多步骤任务中的人工迭代循环。关键机制：一个独立的评估器模型在每轮结束时检查目标条件是否满足，只有通过时才停止循环。

Codex CLI /goal（v0.128.0）：同样的概念，Codex 侧。设置一个可跨会话中断存续的持久目标。默认关闭——需要编辑 TOML 配置才能启用。在一个有记录的实验中：25 小时不间断，1300 万令牌，30,000 行代码。

两者都需要事先明确指定目标。目标越抽象，循环就越昂贵和不可预测。

Boris Cherny 的并行循环工作流
让循环工程进入主流开发者视野的工作流。

设置：

终端中 5 个 Claude Code 实例，按标签页编号

浏览器中同时 5-10 个 Claude 会话

系统通知：仅当智能体需要输入时才查看

一个“传送”命令用于在本地和云端之间传递上下文

CLAUDE.md 作为持久指令层，每个新会话启动时读取

CLAUDE.md 实践是关键洞察。智能体每次犯的错误，修正都写入 CLAUDE.md。未来的会话不会再犯同样的错误。这个文件成为项目知识的累积记录，能在上下文重置后存活。

智能体循环中的记忆
记忆是区分“学会学习的循环”和“只是重复的循环”的东西。没有它，每次迭代都从零开始盲目运行。

生产中使用的四种类型：

情节记忆——先前行动和结果的记录。智能体记得某个特定方法失败了，并避免重复它。

语义记忆——结构化领域知识：架构决策、命名约定、API 文档。

向量记忆——基于相似性的检索。即使原始存储方式与当前请求方式不同，也能找到相关上下文。

基于文件的记忆——Ralph Loop 方法。状态存在于文件系统中。对编码任务来说，比向量存储更简单、更可靠。

CLAUDE.md 是人工策划的语义记忆。比自动生成的记忆更可靠，因为由人类决定放什么进去。

关于智能体系统中记忆架构的更深入探讨，大型行动模型详解涵盖了记忆如何支持长周期任务。

智能体循环也直接连接到 RAG。当循环在执行过程中检索外部知识时，它运行的是一个智能体 RAG 模式——动态决定何时检索和检索什么，而不是一开始只做一次。

故障模式
这些在生产环境中都会出现。每一种都会。

无限循环——没有客观的目标验证。智能体不断优化，因为它总能找到可以改进的东西。AutoGPT 2023 年的事件是典型例子。

目标漂移——智能体追求相关但不同的目标。由模糊的规格说明或将其拉偏的工具结果引起。

上下文溢出——长时间会话填满上下文窗口，推理能力退化。Ralph Loop 的存在就是为了解决这个问题。

静默失败——智能体产生自信的输出，但没有取得实际进展。工具调用在发生，但什么也没有真正改变。最难捕捉。

令牌成本爆炸——单智能体约 4 倍于标准聊天，多智能体约 15 倍。Steinberger 曾承认月度令牌使用量达到 130 万美元。一个有记录的循环事故：一个智能体在五分钟内调用了一个有问题的工具 400 次。

错误传播——循环早期的一个坏决策在后续每一步中被放大。在每个阶段验证，而不仅仅在最后。

循环工程：防护栏
循环工程和“只是运行循环”之间的区别在于，循环工程包含防护栏。这些不是可选的。

硬性迭代上限——在智能体停止并报告当前状态之前的最大循环次数

令牌和成本预算——每次运行的硬性支出限制，从第一天就内置

无进展检测——如果输出状态在迭代间没有变化则退出

断路器——工具调用的重试限制，达到设定尝试次数后清晰报告失败

终止标准——在循环开始前定义“完成”的含义，使用可验证的自动化检查而非智能体自我评估

人工介入检查点——在不可逆操作前强制审查：数据库写入、部署、外部 API 调用

目标不是消除自主性。而是限制它。

智能体操作系统架构一文更深入地探讨了生产系统如何在基础设施层面处理故障检测和重新规划。

选择合适的循环
从最简单的能用的循环开始。只有在你能量化改进时，才增加复杂性。

任务	推荐循环
带重试的单步工具使用	ReAct
需要自我修正的多步任务	ReAct + Reflexion
长代码库重构或构建	Ralph Loop 或 /goal
并行独立研究线程	多智能体编排
具有已知依赖关系的复杂规划	Plan-and-Execute
快速变化的环境	OODA
策略可能需要完全重置	内/外双循环
一个带四个工具的单一 ReAct 智能体处理了大多数现实任务。多智能体系统每会话成本约 15 倍。这个成本需要由产出来证明。

循环工程现在适合所有人吗？
老实回答：不适合。

循环工程确实强大，但令牌成本是真实存在的。单智能体消耗约 4 倍于标准聊天的令牌。多智能体系统消耗约 15 倍。像 Cherny 和 Steinberger 那样跨多个会话运行并行循环，需要目前只有少数公司能无限制提供给自己工程师的那种令牌预算。

Cherny 和 Steinberger 都在公司工作——分别是 Anthropic 和 OpenAI——在这些公司里，这个预算实际上不存在作为约束。这就是这些工作流被开发和优化的环境。

成本是真实的。技术是真实的。这两个事实之间的差距，正是大多数开发者目前所处的位置。

这个差距会缩小。计算资源一向如此。今天价格高昂的东西，几年后就会变成常规基础设施。循环工程现在值得理解，即使以你目前的规模，经济性还不成立。

接下来是什么
智能体工具集正在成为主要的开发者工具——编排逻辑、内存管理、成本控制和可观测性，使循环工程在大规模下可靠

可审计性正在成为必要条件，因为循环在更长的时间范围内采取有重大影响的行动

自我优化的循环——跟踪自身令牌使用并调整方法——正在从实验走向生产

人类的角色正在从 写代码 → 写提示词 → 设计循环 → 构建运行循环的工厂

人类最终是否会被完全移出循环，仍然是一个悬而未决的问题。目前，他们仍然是必需的。但方向是明确的。

现在走在前面的开发者，不是在写更好的提示词。他们在学习循环工程。

常见问题
什么是智能体循环？
智能体循环是一个 AI 智能体的运行周期，包含一个触发器和一个可验证目标。智能体启动、朝目标努力、检查是否已达到、并循环直到达成——每一步都不需要等待新的提示词。

什么是循环工程？
循环工程是设计、指定和维护智能体循环的实践。它涉及定义可验证目标、选择正确的触发器类型、选择正确的循环架构，以及构建防止失控成本和无限循环的防护栏。

智能体循环和自动化有什么区别？
自动化执行一系列步骤。循环内部包含决策——智能体主动评估目标是否已达到，并基于该评估进行循环。关键区别在于目标验证步骤。

我应该从哪种循环类型开始？
ReAct。它适用范围最广、文档最完备，也是大多数生产框架构建的基础。只有在 ReAct 遇到明确限制时才增加复杂性。

为什么智能体循环在生产中会失败？
大多数失败可归结为四个原因：没有硬性停止条件、目标规格不明、长时间会话中的上下文溢出、以及缺少成本控制。

循环工程昂贵吗？
是的，相当昂贵。单智能体消耗约 4 倍于标准聊天的令牌，多智能体系统约 15 倍。按规模运行并行循环——正如开创这些工作流的工程师所做的那样——可能达到七位数的月度令牌账单。随着技术成熟，成本预计会下降，但今天仍然是真实的。

智能体 RAG 与智能体循环有什么关系？
智能体 RAG 是一种循环模式，其中检索被嵌入到推理循环内部——智能体根据其在循环中途发现的内容，动态决定何时检索和检索什么，而不是事先只做一次检索。

结论
转变已经在进行中。提示词是这个时代最初几年 AI 交互的单位。循环工程正在取代它。

从 ReAct 开始。当需要自我修正时加入 Reflexion。当长运行任务触及上下文限制时使用 Ralph Loop 或 /goal。在开始之前明确定义你的目标。在构建复杂性之前先构建防护栏。

现在从智能体 AI 中获益最多的开发者，不是在写聪明的提示词。他们在构建边界良好的循环，可靠地完成任务——并在循环工程成为主流之前就在学习它。
