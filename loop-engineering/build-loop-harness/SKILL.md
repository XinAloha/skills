# 构建 Loop 工具集

1. 从历史缺陷、审查意见、CI 失败和线上信号中列出高频/高损失失败模式；每项指定“预防指南、检测传感器、修复指引、所有者”。
2. 读取 [references/control-catalog.md](references/control-catalog.md)，按行为、可维护性、架构、性能可靠性、安全和知识新鲜度覆盖控制；每条关键约束至少有一个证据源。
3. 读取 [references/feedback-lifecycle.md](references/feedback-lifecycle.md)，将秒级确定性检查放入每轮，把全局/昂贵检查放入集成后或定期扫描。传感器失败信息必须给出位置、违反规则和修复入口。
4. 为运行时目标提供隔离实例和可查询日志、指标、追踪、UI/接口证据；确认每项工具和查询实际存在后才写入契约。
5. 采用最小权限：读、隔离写、外部写、合并/发布/通知逐级授权。高风险动作通过人工闸门，不能被“测试通过”隐式解锁。
6. 将重复两次且可机械判断的问题升级为测试、linter、结构规则或脚本；语义判断保留独立审查与人工抽样。

## 成功标准

Loop 可在最快反馈失败后定位、修复、复验；昂贵传感器有明确频率；运行时证据可由验证者读取，而非由执行者口述。
