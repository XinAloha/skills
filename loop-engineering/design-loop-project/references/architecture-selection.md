# 循环架构选择

先使用单智能体 ReAct：读取状态 → 推理 → 最小动作 → 观察 → 验证 → 持久化。只有下列条件成立才增加复杂度。

| 信号 | 选择 | 必需控制 |
|---|---|---|
| 单步工具失败可重试 | ReAct | 工具超时、重试上限、断路器 |
| 同类失败需要归因并避免重犯 | ReAct + Reflexion | 将精炼失败教训写入任务记忆，限制反思频率 |
| 长代码任务或上下文会膨胀 | Ralph / 目标驱动循环 | 每轮新上下文、磁盘状态、客观停止钩子 |
| 步骤依赖已知且独立项可并行 | Plan-and-Execute | 计划版本、依赖图、阶段验收、重规划条件 |
| 环境输入快速改变 | OODA | 观察后先定向：结合目标、约束、先验再决策 |
| 同一策略连续失败 | 内外双循环 | 内循环停止，外循环重设策略而非原样重试 |
| 任务可拆且第二意见价值高 | 多角色 | 明确产物接口、独立验证者、工作树和汇总者 |

默认使用封闭式循环：预先定义产物、检查、停止和权限。仅在探索阶段使用开放式循环；开放式循环必须有更小预算和更频繁人工检查点。

并行前证明三件事：工作项互不写同一资源、状态可合并、审阅带宽足够。否则串行执行。
