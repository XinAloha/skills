# 审计清单

- 目标：每个成功主张都有命令、查询或批准证据；独立验证者不复用执行者结论。
- 护栏：迭代、时间、成本、并发、工具重试、无进展和硬停止均有阈值。
- 触发：事件过滤、去重键、并发和无发现收尾明确。
- 调度：调度器、时区、运行环境、单次超时、周期预算、最大重试和暂停入口已探测；至少三轮受控运行有证据。
- 隔离：并行写操作使用工作树或等价隔离；共享状态有租约/事务策略。
- 交接：分流记录有来源、风险、目标、工作树、分支、重试、验证裁决、PR/人工入口和下一动作；工作树在审阅前不自动删除。
- 状态：原子更新、检查点、失败指纹、恢复对账和敏感数据规则存在。
- 权限：允许动作最小化；合并、部署、生产写入和外部通知有人工闸门。代码变更在非 `main` 工作树/分支中完成，经草稿 PR 交接；禁止直接推送远端 `main` 和自动合并。
- 反馈：每轮快速检查、集成检查、定期漂移扫描和传感器盲区评估存在。
- 观测：动作、证据、成本、状态转换和失败可追踪，运行时日志/指标/追踪可查询。
- 验证：源码写入任务调用 `$verify-loop-delivery`；验证者与实施者身份不同，默认怀疑并执行真实检查；验证器长期从不拒绝时有盲区复核。
- 人工监督：不确定事项进入收件箱；代码/PR 循环有每日抽样审阅和“无法解释即暂停扩张”的规则。
- 改良：失败与审查意见可进入规则、测试、文档或传感器的受审查改动。
