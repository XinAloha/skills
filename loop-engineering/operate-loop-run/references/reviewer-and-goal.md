# 独立验证者与目标驱动运行

实施者不能作为唯一完成判定者。验证者应独立读取契约、差异和证据，并以“默认有问题”为基线：先运行可执行检查或驱动真实接口，再给结论；只读代码或复述实施者说明不构成通过。

验证者输入：目标、风险优先级检查表、允许工具、通过阈值、拒绝时需要的证据格式。验证者输出：`pass`、`reject` 或 `escalate`，附命令/截图/日志/追踪证据和下一动作。连续多轮从不拒绝的验证器应被审计其盲区。

`/loop` 是定时重复，不自动提供客观终止判断；目标驱动循环才可在每轮以独立验证检查停止条件。只有确认当前平台具备该能力且验证者配置完成后，才使用平台原生命令；否则由运行手册显式执行“检查 → 状态更新 → 决策”。

同一模型的不同提示只能算弱独立性，需标记为风险。高影响任务优先使用独立上下文、独立角色，必要时独立模型或人工验证者。
