# 工作树、分支与交付

对源码写入任务执行以下协议：

1. 在主工作区只做发现和只读验证；确认基线分支、当前状态和任务 ID。
2. 创建一个任务分支和工作树，例如 `agent/<task-id>` 与 `../wt-<task-id>`；先确认两者都不指向 `main`。一个任务只能有一个写工作树。
3. 将工作树路径、分支、租约、基线提交、预算和负责人写入状态。并行上限按人类可审阅 PR 的数量设定，不按机器可启动数量设定。
4. 在工作树内实施、测试、保存证据；主工作区不得接收智能体写入。崩溃后保留工作树供恢复或人工检查，不自动丢弃。
5. 通过验证后仅推送任务分支并创建草稿 PR（若契约允许 PR API）。PR 包含目标、变更、验证证据、风险、回滚和未决问题。
6. 人工批准后才可合并。自动合并、直接 `push origin main`、在 `main` 上修改、删除未审阅工作树均为拒绝动作。

在开始前进行能力探测：`git worktree list`、当前分支、远端分支保护和 PR 工具权限。任何探测失败都使交付转为 `blocked`，而不是回退到直接写主分支。
