# 运行 Loop 工程

1. 读取契约、状态、最近证据和项目规则；先执行只读预检。能力或权限未验证时转为阻断，不尝试猜测平台命令。
2. 按 [references/runtime-protocol.md](references/runtime-protocol.md) 接收或创建分流项；用去重键确认未被处理，按契约申请租约/并发槽。
3. 对会写入仓库的任务创建独立工作树或等价隔离。并行任务不得共享写目录、分支或状态写者；不能隔离则串行。
4. 执行固定轮次：读取 → 定向 → 最小行动 → 观察 → 快速验证 → 状态/证据持久化 → 决策。触发无进展或重复失败时按契约重规划或升级。
5. 将实施者与验证者分离。验证者仅根据契约、差异、命令输出和运行时证据判定；未通过则把反馈写回任务状态。
6. 通过后仅创建待交接产物（例如补丁、PR 草稿、报告）；合并、部署、生产写入、外部通知必须等待批准闸门。
7. 释放租约、归档证据、记录成本/未决风险和下一动作。中断后按 [references/recovery-protocol.md](references/recovery-protocol.md) 对账再恢复。

## 成功标准

每轮可追踪、可恢复、可验证；并行运行不互相覆盖；所有高风险行为都能定位到明确的人类批准记录。
