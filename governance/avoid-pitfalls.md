# 反面案例与避坑

> **核心原则**：不是所有开源代码都值得学习，要有辨别能力，避免"屎山互鉴"

## 不值得学习的信号

### 1. 代码质量红旗

| 信号 | 说明 | 示例 |
|------|------|------|
| 无单元测试 | 代码没有测试覆盖，质量无法保证 | 测试目录为空或覆盖率 < 50% |
| 硬编码满天飞 | 配置写死在代码里 | `URL = "http://fixed-server.com"` |
| 异常处理缺失 | try-except 捕获所有异常后 pass | `except: pass` |
| 重复代码块 | 复制粘贴式编程 | 同样逻辑在不同文件出现 3+ 次 |
| 无类型注解 | Python 代码无任何类型提示 | 函数参数和返回值无注解 |
| 魔法数字 | 代码中充斥无法理解的数字 | `if code == 92:` 无注释说明 |

### 2. 数据源可信度红旗

| 信号 | 风险 | 避坑建议 |
|------|------|---------|
| 无数据来源说明 | 数据来历不明，可能存在法律风险 | 优先选择标注数据来源的项目 |
| 个人维护且无备份 | 作者随时可能弃坑 | 检查最近 commit 时间和 issue 响应速度 |
| 无数据校验逻辑 | 数据错误无法发现 | 查看是否有数据验证代码 |
| 单数据源无对比 | 数据错误无交叉验证 | 避免完全依赖单一未知源 |
| 爬虫绕过反爬 | 可能违反服务条款 | 检查是否有合理请求间隔和 User-Agent |

### 3. 项目可信度红旗

| 信号 | 风险 | 检查方法 |
|------|------|---------|
| GitHub Star 数极少 (< 100) | 社区认可度低 | 查看 star/fork 趋势 |
| 长期无更新 (> 1 年) | 可能已经废弃 | 查看 commit 历史 |
| 大量未处理 Issue | 维护不积极 | issue 回复率 < 30% |
| 无文档或文档过时 | 使用困难 | README 是否完整 |
| 许可证模糊 | 法律风险 | 检查 LICENSE 文件 |

## 反面案例分析模板

```markdown
# analysis/negative_case_[项目名].md

## 项目信息
- 名称：xxx
- 地址：https://github.com/xxx/xxx
- Star 数：50
- 最后更新：2023-01-01（距今 1.5 年）

## 发现的红旗
### 代码质量问题
- [x] 硬编码 API 密钥
- [x] 异常处理 pass

### 数据源问题
- [x] 无数据来源声明

### 可信度问题
- [x] 长期无维护

## 结论
**不学习此项目**，因为代码质量差、数据源不可靠、项目已废弃。

## 替代方案
如需类似功能，建议使用 [akshare/vnpy/其他可信项目]
```

## 避坑检查清单

在决定学习一个项目前，必须检查：

- [ ] **代码层面**：有单元测试吗？覆盖率 > 70%？
- [ ] **代码层面**：有类型注解吗？函数长度 < 50 行？
- [ ] **数据源**：数据来源合法吗？有说明吗？
- [ ] **数据源**：有数据校验机制吗？
- [ ] **项目健康**：最近 3 个月有更新吗？
- [ ] **项目健康**：Issue 回复及时吗？
- [ ] **社区**：Star > 500？有实际使用案例？
- [ ] **法律**：许可证明确吗？MIT/Apache/BSD 优先

**只要有一个关键项不通过，就不要学习该项目！**

## 取长补短策略

学习前问自己 3 个问题：

1. 这段代码的【优点】是什么？ → 值得我学习的点
2. 这段代码的【缺点】是什么？ → 我要避免的坑
3. 这段代码【适合我的场景】吗？ → 量体裁衣，不盲目照搬

| 项目 | 可取之处 | 要避免的 | 我们的做法 |
|------|---------|---------|-----------|
| **akshare** | 多源适配策略、异常分类处理 | 部分模块代码冗长 | 提取策略模式，保持简洁 |
| **vnpy** | 数据库 ORM 设计、事务管理 | 整体架构过重 | 只提取数据管理模块 |
