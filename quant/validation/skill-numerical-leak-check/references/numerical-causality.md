# 数值因果性检查

数值因果性检查关注的是：历史输出是否会因为未来输入存在、缺失或变化而改变。

## 它能发现什么

- 使用未来行、负向 shift、center rolling、forward window。
- 全样本标准化、全样本 rank、全样本 scaler。
- 先用完整数据 fit 再回填历史的模型或变换。
- 标签、特征、信号之间的时间对齐错误。
- 缓存或状态把 full run 的未来信息带入 prefix run。
- 截面、panel 或调仓逻辑中的非因果依赖。

## 它可能漏掉什么

- checkpoint 没覆盖到泄露暴露位置。
- 合成或测试输入没有触发含泄露的代码分支。
- 未来数据改变后输出被 sign、clip、rank、threshold 压成相同值。
- 差异低于容忍度，或 NaN/inf 处理掩盖了差异。
- 真实生产中的日历、session、换月、复权、停复牌、成分变化没有被测试输入覆盖。
- adapter 或 wrapper 没有复现生产调用路径。
- 目标代码有随机性、全局状态或缓存，导致结果不稳定。

## 与静态扫描的关系

静态扫描能快速发现明显危险模式，例如 `shift(-1)` 或 `center=True`。数值检查能发现静态扫描难以判断的间接依赖。两者互补；当结果冲突时，优先分析目标代码和失败 cut，而不是机械相信某一边。

## 结论措辞

推荐写法：

> 当前数值测试未发现未来输入会改变历史输出。

避免写法：

> 证明该因子没有未来函数。

因为数值检查只能覆盖本次 adapter、输入、checkpoint、扰动和比较口径。
