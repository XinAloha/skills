# Deep Modules - 深模块

来自《A Philosophy of Software Design》（John Ousterhout）：

**深模块** = 小接口 + 大实现

```
┌─────────────────────┐
│   小接口             │  ← 几个方法、简单参数
├─────────────────────┤
│                     │
│                     │
│   深实现             │  ← 复杂逻辑被隐藏
│                     │
│                     │
└─────────────────────┘
```

**浅模块** = 大接口 + 小实现（要避免）

```
┌─────────────────────────────────┐
│       大接口                     │  ← 很多方法、复杂参数
├─────────────────────────────────┤
│  薄实现                          │  ← 只是透传
└─────────────────────────────────┘
```

## 设计接口时问

- 能不能减少方法数量？
- 能不能简化参数？
- 能不能在内部隐藏更多复杂度？

## 本项目示例

**深模块的好榜样**：`BaseCollector.fetch_daily(symbol, start, end) -> DataFrame`

- 接口：3 个参数 + 标准化的 DataFrame schema。
- 实现：内部处理重试、限流、字段映射、停牌补全、复权调整、数据源降级（Tushare → AKShare → adata）。

**浅模块的反例**：一个 `data_collection.utils.helpers` 把 7 个互不相关的工具函数堆在一起，每个函数只有 3 行——接口（"看一下名字猜功能"）几乎和实现一样复杂。
