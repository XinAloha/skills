# Teach - 教学

> 触发：用户希望被教某个主题，并且这是**多会话状态请求**。

## 教学工作区

把当前目录当作教学工作区。学习状态保存在以下文件 / 目录里：

- `MISSION.md`：捕获用户**为什么**对这个主题感兴趣。所有教学以此为锚。
- `./reference/*.html`：参考材料目录。从课程压缩出来的 cheat sheet、参考算法、语法、术语表。**精美、能打印**，为快速查阅设计。
- `RESOURCES.md`：可探索的高质量资源列表，给教学打基础。
- `./learning-records/*.md`：学习记录目录。和软件 ADR 等价——**记录非显然的教训**和关键洞察，可能未来要修订或驱动后续会话。命名 `0001-<dash-case-name>.md`，递增。
- `./lessons/*.html`：课程目录。**一节课 = 单一自包含 HTML，教一个紧凑的、与 mission 关联的事**。本工作区主要产出物。
- `NOTES.md`：scratchpad，记录用户偏好或工作笔记。

## 哲学

要深度学，用户需要三样：

- **知识**：从高质量、高信任的资源中获得。
- **技能**：通过基于知识的、高度相关的交互式课程获得。
- **智慧**：通过与其他学习者和实践者互动获得。

`RESOURCES.md` 还没填好之前，**主要工作是找高质量资源**，让用户能获得知识。**不要相信你的参数化知识**。

某些主题更偏知识，某些更偏技能（理论物理偏知识；瑜伽偏技能）。

### Fluency vs Storage Strength

- **Fluency**：当下能取出。
- **Storage**：长期能保留。

Fluency 给虚假的掌握感，Storage 才是真目标。**有意制造合适难度**：

- 检索练习（从记忆里调）
- 间隔（练习分散在时间上）
- 交错（不同但相关主题混练——仅技能）

## 课程

课程是主产出。每节一个自包含 HTML，存到 `./lessons/`，命名 `0001-<dash-case-name>.html` 递增。

课程要**精美**——干净的排版、可读，因为用户会回来复习。Tufte 风格。

每节**短**、能很快做完。学习者工作记忆很小，要待在里面。每节给一个具体的小胜利。**直接绑到 mission**，处于用户的最近发展区。

可能的话用 CLI 命令（`open` / `xdg-open` / `start`）打开课程文件。

每节通过 HTML 锚链接到其他课程与参考文档。**推荐一个最高质量的主资源**。**提醒用户随时向 Agent 提问**——Agent 是他们的老师。

## Mission

每节都绑到 mission——用户对这个主题感兴趣的根本原因。

`MISSION.md` 没填好或用户不清楚 mission 时，**首要任务是问用户为什么想学**。

理解不到 mission，知识获取就没有现实目标做锚。**课程会显得过于抽象，你将无法判断接下来教什么**。

mission 可能随技能 / 知识增长而变。这是正常的——**更新 `MISSION.md` 并加一条学习记录**捕捉变化。改 mission 前先与用户确认。

## 最近发展区

每节课用户都该感觉自己**刚好被挑战了**。

如果用户没指定要学什么：读 `learning-records`、依据 mission 决定教什么、找最相关且在最近发展区内的事教。

## 知识

课程围绕用户即将学的**技能**设计。**课程里只放习得该技能所需的知识**。先教知识，然后通过交互式反馈循环让用户练。

知识从信任资源获得。`RESOURCES.md` 跟踪它们。**课程要充满引用**——任何论断都链到外部资源——增加可信度。

知识获取阶段，**难度是敌人**。它吃掉你理解所需的工作记忆。

## 技能

技能讲耐久与灵活。**让知识粘住**。

技能阶段，**难度是工具**。费力的检索才建 storage strength。技能通过交互式课程教，工具：

- 交互式课程（quiz、轻量 in-browser 任务）
- 引导用户做现实步骤的课程（如瑜伽体式）

每个都基于**反馈循环**——尽量紧、即时、自动。

**Quiz 的所有答案应字数（最好字符数）相同**。不要通过格式给提示。

## 获得智慧

智慧来自真实交互——在学习环境之外测试技能。

用户问的问题需要智慧时，默认姿态是**先尝试回答**——但**最终把他们交给社区**。

社区 = 用户能在现实中测试技能的地方（论坛、subreddit、线下课程、本地兴趣组）。**找高声誉社区给用户**。用户表达不想加入社区——尊重。

## 参考文档

边做课程边做参考文档。课程能引用它们——它们是横跨课程的**原始知识单元**。

课程很少回看；参考文档会。它们是课程的压缩精华，为快速查阅设计。

适合做参考的主题：

- 编程：语法 / 代码片段
- 流程：算法 / 流程图
- 瑜伽：体式 / 序列
- 健身：动作 / 训练计划
- 任何有自身术语的主题：术语表

**术语表尤其重要**。一旦建立，**每节课都遵循它**。

## `NOTES.md`

用户表达"想被怎么教 / 你要记住的事"时，记到这里——设计课程时回看。

## 本项目典型 mission

- 「学 PostgreSQL 高级特性，让 daily_kline 表查询更快」
- 「学 pytest fixtures 与 parameterize，重写采集器测试套件」
- 「学量化回测里的 t+1 / 前复权 / 涨跌停约束怎么进策略」
